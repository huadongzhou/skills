# cognition — 知识深度树

给定任意实体，产出一份文档：读者读完，理解被**翻过来**，从「听过」变成「懂了，而且原来的理解是错的」。价值在**反转**，即把默认认知与真相之间的距离摆出来；因此共识压缩到一句话，反直觉处展开。

## 三件套

每个节点交三样东西，三种视角看同一个点：

| 件 | 是什么 | 作用 | 判据 |
|---|---|---|---|
| 黑话 | 圈内实际在用的词 + 它真正指什么 | 让读者能听懂、也能说出行话 | 是真实术语，不是自造词 |
| 白话 | 同一件事的零术语翻译 | 让外行也能懂 | 通篇不含术语 |
| 案例 | 有名有姓、可验证的具体实例 | 让抽象落地 | 谁 / 何时 / 发生了什么，可追溯 |

可选补件，按节点需要加：**数字**（一个能改变量级感的数）、**反例**（一次失败或翻车）、**类比**（一个外行已知的近似物）。

## 反转

**反转** = 一句话把默认认知翻过来，形如「你以为 A，其实 B，因为 C」。

判据：单独拿给一个外行看，他的反应是「等等，真的？」。若反应是「嗯，有道理」，那是常识而非反转，删掉。

每个节点至少一条反转；全篇反转按树序排列，读者顺着往下读，认知被一层层掀开。反转的主色调随领域变化，见 [`references/domains.md`](references/domains.md)。

## 知识深度树 · 九维

任何实体都可从九个维度审问，从表层到深层。九维对全领域通用，不同领域只按覆盖矩阵增删主次与并入。

| # | 维度 | 通用问题 |
|---|---|---|
| 1 | 身份 | 它是什么 |
| 2 | 构成 | 它由什么组成 |
| 3 | 谱系 | 它从哪来 |
| 4 | 机制 | 它怎么运转 |
| 5 | 坐标 | 它与什么相连 |
| 6 | 动力 | 谁在推动它 |
| 7 | 边界 | 它做不到什么 |
| 8 | 争议 | 分歧在哪 |
| 9 | 意义 | 它意味着什么 |

逐维度的填法（查什么、反转藏哪、黑话样本、好案例）与两套领域读法 → [`references/dimensions.md`](references/dimensions.md)。
领域判定、覆盖矩阵（哪些维展开、哪些简述、哪些并入及去向）、各领域反转主色调 → [`references/domains.md`](references/domains.md)。

## 操作

### 第一步 · 立树

1. 判定领域（十一个，可多标）：技术产品 / 组织公司 / 制度规则 / 概念理论 / 作品语言 / 事件现象 / 人物 / 物质材料 / 生物系统 / 地理天文 / 数学形式；
2. 按覆盖矩阵在九维上定主次与并入，定稿骨架；
3. 为每个保留维度写下一句「本节要回答的问题」，这句是后面检索的靶子。

**完成判据**：领域已判定；每个保留维度都挂着一句待答问题；并入的维度已标出去向。

### 第二步 · 检索取证

逐维度联网检索，为每句待答问题取证。

- 优先一手与权威来源，记录来源链接与日期；
- 交叉验证：反转这类反直觉结论，至少两个独立来源；
- 检索不到就写「检索无果：<缺什么>」，用留白代替推测；
- 时效性实体标注「截至 <日期>」。

**完成判据**：每个待答问题都有至少一条可追溯来源，或一条明确的「检索无果」。

### 第三步 · 逐节点落笔

按树序逐维度写，每个节点交齐三件套与反转。

- 反转先行：先写反转，再用三件套解释它；
- 反转取该领域的主色调；
- 共识只作为反转的靶子复述一句，其余篇幅留给反直觉处；
- 案例真实可追溯，用真实事件而非虚构示例。

**完成判据**：每个保留维度三件套齐全、反转齐备，且每条反转都指出它推翻的具体默认认知、附至少一个支撑来源。

### 第四步 · 成文交付

按 [`templates/knowledge-doc.md`](templates/knowledge-doc.md) 成文，输出到用户指定位置，未指定则当前工作目录。

**完成判据**：模板每个占位符已填、无遗留提示注释、无模板写作说明残留（「节点块」「按树序填以下维度」这类给作者看的话不得出现在成文里）；树序完整无断档。

## 异常与兜底

流程假设环境理想，实操常遇下列异常。命中即按表执行，绝不静默跳过。

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 检索工具不可用或无返回 | 换用其它检索入口重试一次 | 转纯推理推进，在该节点标注「检索无果：工具不可用」 |
| 反转的两条来源互相矛盾 | 并列两说，标注分歧点与各自来源 | 无法判断孰是时，改归入「争议」维度，不写成反转 |
| 实体跨多个领域、无法定主 | 取覆盖最广的领域立骨架，其余作次领域读法 | 仍难判定时，列出候选领域问用户后再立树 |
| 某维度无法归属且无内容可填 | 并入最近维度并标出去向 | 保留该维度，写「待补充：<缺什么、去哪找>」 |
| 私有或虚构实体无公开来源 | 全程留白，标「检索无果：<缺什么>」 | 以用户提供的一手信息为唯一来源，并标注来源类型 |
| 成文写盘失败 | 换用用户指定或当前目录重试一次 | 将成文内容原样输出到对话，由用户自行落盘 |

**兜底原则**：宁可留白，不可编造。某节点标注「检索无果」时，第三步的来源要求对该节点自动豁免，改以「已标注检索无果」为完成条件。

## 纪律

- **不编造**：检索无果处留白并标注，本技能的载荷是反直觉结论，编造的代价最高。
- **反转有据**：反差由事实支撑，由修辞制造的反差一律回炉。
- **全领域同一把尺**：遇到难套的实体先查覆盖矩阵，不为单个实体新造维度。
- **语言跟随用户**（默认中文）；黑话保留圈内原词，白话负责翻译。
- 收尾汇报：领域判定、维度主次与并入、各节点反转数、检索无果项、时效标注。
