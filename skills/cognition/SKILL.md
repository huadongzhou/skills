# cognition — 知识深度树

给定任意实体，产出一份文档：读者读完，理解被**翻过来**，从「听过」变成「懂了，而且原来的理解是错的」。价值在**反转**，即把默认认知与真相之间的距离摆出来；因此共识压缩到一句话，反直觉处展开。

## 三件套

每个**展开维度（●）**的节点交三样东西，三种视角看同一个点：

| 件 | 是什么 | 作用 | 判据 |
|---|---|---|---|
| 黑话 | 圈内实际在用的词 + 它真正指什么 | 让读者能听懂、也能说出行话 | 是真实术语，不是自造词 |
| 白话 | 同一件事的零术语翻译 | 让外行也能懂 | 通篇不含术语 |
| 案例 | 有名有姓、可验证的具体实例 | 让抽象落地 | 谁 / 何时 / 发生了什么，可追溯 |

**简述维度（○）**只交一句定位与一条反转，不展开三件套。可选补件，按节点需要加：**数字**（一个能改变量级感的数）、**反例**（一次失败或翻车）、**类比**（一个外行已知的近似物）。

## 反转

**反转** = 一句话把默认认知翻过来，形如「你以为 A，其实 B，因为 C」。

判据：单独拿给一个外行看，他的反应是「等等，真的？」。若反应是「嗯，有道理」，那是常识而非反转，删掉。

每个**有来源支撑**的节点至少一条反转（例外见「第三步」完成判据的豁免态②）；全篇反转按树序排列，读者顺着往下读，认知被一层层掀开。反转的主色调随领域变化，见 [`references/domains.md`](references/domains.md)。

**不得为凑数而造反转**：某节点确实没有反直觉结论时，写明「本维无反直觉结论：<原因>」，凭据按该节点来源类型给：**检索型**附已尝试的检索式（≥2 条且彼此不同，且**须靶向反转**——以**待验命题**为主体，含实体名与具体待验的反直觉点，并附检索日期与返回条数；仅含实体名的宽泛检索式不算凭据）；**来源为用户提供**（私有／内部实体，见「异常与兜底」）只写「来源：用户提供」，**不要求检索式**。检索式记入附录，正文只写原因。该状态在「第三步」完成判据中列为豁免态。计入收尾汇报；既不得保留弱反转充数，也不得新造反转。

## 知识深度树 · 九维

任何实体都可从九个维度审问，从表层到深层。九维对全领域通用，不同领域只按覆盖矩阵增删主次与并入。

| # | 维度 | 通用问题 |
|---|---|---|
| 1 | 身份 | 它是什么 |
| 2 | 构成 | 它由什么组成 |
| 3 | 谱系 | 它从哪来 |
| 4 | 机制 | 它怎么运转 |
| 5 | 坐标 | 它与什么相连 |
| 6 | 动力 | 谁在推动它 |
| 7 | 边界 | 它做不到什么 |
| 8 | 争议 | 分歧在哪 |
| 9 | 意义 | 它意味着什么 |

逐维度的填法（查什么、反转藏哪、黑话样本、好案例）与两套领域读法 → [`references/dimensions.md`](references/dimensions.md)。
领域判定、覆盖矩阵（哪些维展开、哪些简述、哪些并入及去向）、各领域反转主色调 → [`references/domains.md`](references/domains.md)。

## 操作

### 第一步 · 立树

1. 判定领域（十一个，可多标）：技术产品 / 组织公司 / 制度规则 / 概念理论 / 作品语言 / 事件现象 / 人物 / 物质材料 / 生物系统 / 地理天文 / 数学形式；
2. 按覆盖矩阵在九维上定主次与并入，定稿骨架；
3. 为每个保留维度写下一句「本节要回答的问题」，这句是后面检索的靶子。

**完成判据**：领域已判定；每个保留维度都挂着一句待答问题；并入的维度已标出去向。

**🔴 CHECKPOINT · 🛑 STOP**：骨架定稿（领域判定、九维主次与并入、各维待答问题）先交用户确认，确认后再进入第二步。同一轮内若还需向用户索取一手信息（见「异常与兜底」），可与本检查点**合并为一次输出**，不必分两轮往返。

> **跳过条件（唯一，后三步通用）**：用户本次请求的原话**同时**含**产出动词**（深挖／生成／构建／保存／写／落盘／输出）与**免确认词**——免确认词指下列任一：`不用问我`／`不用确认`／`无需确认`／`别问`／`直接来`，或原话出现「直接」且同时满足三个条件：其后 6 字内出现任一产出动词、中间**不含标点**、「直接」后首字**不是** `说`／`讲`／`问`／`答`（覆盖「直接生成」「直接用推理写」「直接输出」「直接给我写」；排除「我直接说深挖 X」「直接说重点写一份 X」）。**否定与延后语境一律不免确认**（两处都查）：①「直接」**前** 4 字内出现 `不`／`别`／`勿`／`先`／`等`／`再`／`待`；②任一命中词**后** 8 字内出现 `先`／`等`／`再`／`待`／`稍后`／`之后`——但该词**前 2 字内**若为 `不`／`别`／`勿`／`无`／`没`，则不计（如「不用先问我」「我不等确认」不算延后）。**疑问或假设语气不触发**（句末 `？`／`吗`／`能不能`／`如果`／`假如`）。**未命中即视为不免确认**，不得自行外扩。跳过时须在回复首行引用该原话。本旁路同时覆盖「异常与兜底」表中一切需要用户交互的修复项（索取一手信息、索取一手案例、列候选问用户）：命中时跳过交互，直接走该行的「仍失败兜底」。

### 第二步 · 检索取证

逐维度联网检索，为每句待答问题取证。

- 优先一手与权威来源，记录来源链接与日期；
- 交叉验证：反转这类反直觉结论，至少两个独立来源；
- 检索不到就按**留白标记**（见「异常与兜底」）留白，用留白代替推测；
- 时效性实体标注「截至 <日期>」。

**完成判据**：每个待答问题都留下一条可追溯的取证记录——①已采用的来源；②**检索型留白**（查了没查到）附已尝试的检索式（≥2 条且彼此不同）与去哪找；③**索取型留白**（该问用户）附写明的索取项；④**工具不可用留白**（检索入口全部失败、未执行检索）标注类型与补的办法。四者皆无即为未完成。

### 第三步 · 逐节点落笔

按树序逐维度写，每个节点交齐三件套与反转。

- 反转先行：先写反转，再用三件套解释它；
- 反转取该领域的主色调；
- 共识只作为反转的靶子复述一句，其余篇幅留给反直觉处；
- 案例真实可追溯，用真实事件而非虚构示例。

**完成判据**：每个**展开维度（●）**三件套齐全（案例位留白时按两件套交付；整节点留白时不产出三件套，均见异常表该行）、反转齐备；**简述维度（○）**至少有一句定位与一条反转。**两种豁免态不受「三件套齐全」与「至少一条反转」约束**：①**整节点**按留白标记留白的节点；②已按「反转」节写明「本维无反直觉结论：<原因>」并附凭据的节点。其余节点，每条反转都须指出它推翻的具体默认认知、附**至少两个独立来源**（仅找到一条时按异常表该行降级）。

### 第四步 · 成文交付

**🔴 CHECKPOINT · 🛑 STOP**：成文前先把树序大纲与全部留白项列给用户，确认后再落盘。跳过条件与第一步相同，跳过时须在回复首行引用该原话，并改为随成文一并列出（写入文末「交付说明」节）。**「交付说明」与「待验证假设」两节属模板外扩展，均不计为写作说明残留。**

按 [`templates/knowledge-doc.md`](templates/knowledge-doc.md) 成文，输出到用户指定位置，未指定则当前工作目录。

**完成判据**：模板每个占位符已填、无遗留提示注释、无模板写作说明残留（「节点块」「按树序填以下维度」这类给作者看的话不得出现在成文里）；树序完整无断档。

## 异常与兜底

流程假设环境理想，实操常遇下列异常。命中即按表执行，绝不静默跳过。

**留白标记（正文与汇报的唯一格式）**：`<类型前缀>：<缺什么>｜去哪找：<补的办法>`。类型前缀只有三个取值：`检索无果`（检索型）／`待用户提供`（索取型）／`未检索`（工具不可用）。不得另造「待补充」等变体。**已尝试的检索式不进正文标记**，统一记入附录「留白与检索记录」节（豁免态②的凭据检索式、同名无关实体的记录也记入该节）；该节条目是本标记唯一被允许的扩展形态：`- \`<前缀>\` <缺什么>｜去哪找：<补的办法>｜已尝试的检索式：<检索型必填 ≥2 条；其余两类写「不适用」>｜日期：<检索日期>｜返回条数：<n>`。节名沿用「留白与检索记录」，不因承载多类记录而另立新节。

**留白分三类**：(a) **检索型**——公开实体查了没查到（**返回条数 0 条属此类**），须附已尝试的检索式（≥2 条且彼此不同）；(b) **索取型**——私有或内部实体无公开来源，只能问用户，**不要求检索式**；(c) **工具不可用**——检索入口**调用失败、未执行检索**（**仅此情形归此类**），**不要求检索式**，补的办法是「换入口或稍后重试」。**案例位留白不是独立一类**，按其原因归入 (a) 或 (b)。

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| **实测**检索工具不可用，或无返回（工具层失败） | 换用其它检索入口重试一次 | 该节点按**工具不可用留白**处理，只写 `未检索：<缺什么>｜去哪找：换入口或稍后重试`；如需保留推理线索，另置于文末「待验证假设」区，**不计入三件套、不充当反转来源** |
| 用户陈述的环境状态与实测不符（如称「检索工具不可用」但入口可用） | 以**实测为准**继续正常检索，并在回复中说明该差异 | 以实测完成检索即可，**不产生留白**；若换入口后仍无返回，走上一行（工具不可用留白）。本行前提是实测可用，故不适用于「实测确无返回」 |
| 检索命中同名无关实体 | 逐条核对来源是否指向本实体（可核验特征：与用户给的定义/领域一致，或出自本实体官方或一手渠道）；命中的无关同名实体逐条记入附录「留白与检索记录」节，前缀用 `检索无果` | 命中的全部指向无关实体时，按「私有或内部实体无公开来源；或公开实体的案例位检索不到」行处理；无法判断本实体是哪一个时，按「实体跨多个领域、无法定主」行处理 |
| 反转的来源互相矛盾 | 并列两说，标注分歧点与各自来源 | 无法判断孰是时，改归入「争议」维度，不写成反转 |
| 反转只找到一条独立来源 | 换检索式、换语言、查一手文件再试一次 | 降级为「单源存疑」：反转句末标 `（单源存疑）`，来源处并列写出该唯一来源，计入收尾汇报；或改归「争议」维度。**不得补造第二条来源** |
| 私有或内部实体无公开来源；或公开实体的案例位检索不到 | 私有实体：向用户索取一手信息／一手案例（定义／用途／关键事件），标注「用户提供，未经外部核验」；公开实体案例位：换检索式再试一次 | 私有实体无公开来源＝**整节点留白**，按**索取型** `待用户提供：<缺什么>｜去哪找：问用户`，不产出三件套与反转；公开实体案例位＝**案例位留白**，按**检索型** `检索无果：…`，三件套按两件套交付，不计为未完成。命中跳过条件时不再索取，直接落到本条 |
| 实体跨多个领域、无法定主 | 取覆盖最广的领域立骨架，其余作次领域读法 | 仍难判定时，列出候选领域问用户后再立树（命中跳过条件时取覆盖最广者，并在交付时列出候选） |
| 某维度无法归属且无内容可填 | 并入最近维度并标出去向 | 保留该维度，按留白标记留白（前缀按实际类型取） |
| 成文写盘失败 | 换用用户指定或当前目录重试一次 | 将成文内容原样输出到对话，由用户自行落盘 |

**兜底原则**：宁可留白，不可编造。**整节点**按留白标记留白时，第三步的要求降为：该节点只写留白标记，不产出反转、不产出三件套。**案例位**留白不适用本条——三件套按两件套交付（见异常表该行）。反转只留给有来源支撑的节点。

## 纪律

- **不编造**：检索不到就按留白标记留白，不推测、不补造来源与案例；本技能的载荷是反直觉结论，编造的代价最高。
- **反转有据**：反差由事实支撑，由修辞制造的反差一律回炉。
- **全领域同一把尺**：遇到难套的实体先查覆盖矩阵，不为单个实体新造维度。
- **语言跟随用户**（默认中文）；黑话保留圈内原词，白话负责翻译。
- 收尾汇报：领域判定、维度主次与并入、各节点反转数、**无反转节点及其原因与凭据**、**单源存疑节点**、**案例位留白节点数**、留白项（注明**检索型／索取型／工具不可用**；检索型附检索式 ≥2 条及日期、返回条数，其余两类不附）、时效标注。
