# foundation — 项目四文档基建

为项目准备稳定的根级上下文文档，让任意代码助手进入项目即拥有一致的认知基础。

## 管辖范围（硬约束）

- 管理的项目文档只有四份，且只位于**仓库根目录**：`AGENTS.md`、`DESIGN.md`、`TODO.md`、`DMS.md`。
- 除下一条的例外外，其余任何文档（README.md、CLAUDE.md、docs/ 等）不属于本技能：不创建、不修改、不迁移，仅允许作为「解读项目」时的只读信息来源。
- **唯一例外**：仓库根 `templates/` 下的四份同名模板是本技能的工作产物，不受上一条「不创建」约束。判定分两层，先目录层、后文件层：
  1. **目录层（仅此一条门禁）**：目录不存在、**目录为空**，或目录内**至少含一个本技能痕迹**（任一四份同名模板文件，或 `<!-- 反哺：` 标记）→ 属于本技能，可写入；目录已存在、内有其它文件、且**不含任何**本技能痕迹 → 视为项目自有目录，整目录不写入并说明，用户确认后照常逐份写入。
  2. **文件层（逐份）**：同名文件不存在、或与本技能自带模板**有公共章节重合**时，该份可写入；同名文件存在且**完全无**公共章节重合时，跳过该份并说明。**已有 1～3 份的部分状态同样可写**，不受份数影响。
  目录内的其它无关文件一律**不创建、不修改、不删除**。除此之外不得创建任何新文件。

## 两个 templates/：读哪里、写哪里

| 位置 | 角色 |
|---|---|
| 技能自带的 `templates/<名>.md` | **只读兜底基准**。仓库根无同名模板时读它。技能安装目录只读，任何情况下都不得写入。 |
| 仓库根的 `templates/<名>.md` | **同步的写入目标**，也是初始化/更新的**优先基准**（同步产物优先）。仓库里没有时，由**同步**操作负责从技能自带模板复制出同名文件再写回；初始化与更新只读该目录、不写入。 |

**读取优先级（唯一规则）**：`<仓库根>/templates/<名>.md` 存在就用它，不存在才用技能自带的同名模板。这条让「同步」的反哺成果能回流到后续的初始化与更新，闭环成立。唯一的例外是「污染防护」判定的损坏情形，按该条处置。

**污染防护**：以仓库版本为基准前，先与技能自带模板比对公共章节。**公共章节＝模板中除 H1 之外的标题与表头**；标题比对按「操作二」的归一化语义（含 `#` 层级一致），**表头仅按通配文本相同比对，不判层级**。**公共章节完全缺失**（一个都对不上）＝该文件不是本技能产物，按「管辖范围」的目录层/文件层判据**跳过该份**，不覆盖、不写入；**公共章节部分缺失**（部分对得上）属模板损坏，走「异常与兜底」的补齐路径，不跳过；**公共内容被改写**时以技能自带为准并在汇报中提示（改写属污染，不属项目自有）。反哺写入的段落带 `<!-- 反哺：<日期> 来源 <文档> -->` 标记（它是挖空点，见「模板机制」）。**撤销只作用于模板**——按标记移除该次反哺的标题与段落，**项目文档一律不动**（方向单一）；撤销后模板与项目文档重新出现差异属正常状态，由用户后续自行决定是否再同步，技能不自动回滚、也不代为清理项目文档侧。

## 文档定位

| 文档 | 是什么 | 解读项目时的主要来源 |
|---|---|---|
| AGENTS.md | 默认上下文 | package.json、构建/lint 配置、源码目录树、README |
| DESIGN.md | 设计上下文 | 设计稿、demo HTML、主题样式与令牌文件 |
| TODO.md | 待办账本 | 需求输入、issue、源码 TODO 注释、git log |
| DMS.md | 文档管理规范 | 现有目录结构、既有文档的命名与存放位置、git log |

上表只给主要来源；每份文档的完整章节结构与挖空点，以模板正文为准。

## 模板机制

`templates/<名>.md` = 公共结构与公共内容（跨项目通用，原样保留） + 挖空点。挖空点有四种形态，等价对待：

1. `<!-- 生成提示：... -->` 注释；
2. `{{占位符}}`；
3. 以正文自述「属挖空点／格式示范」的块（如 `templates/TODO.md` 的格式示范块）；
4. `<!-- 反哺：<日期> 来源 <文档> -->` 标记及其所辖标题与段落——只存在于仓库根模板，且**指向的是别的项目**，初始化/更新时一律删除。

**计数口径**：挖空点数 = 上述四形态合计；空表头等悬空结构不计入，按填空规则 4 处置。

整套机制是完形填空：**初始化/更新 = 填空**（按项目事实填每个挖空点），**同步 = 挖空**（把项目文档长出的结构剜去项目特性、还原成挖空点写回模板）。

填空规则：

1. 公共内容原样带入；
2. 逐个挖空点按生成提示解读项目、产出内容，随后删除提示注释、未使用的占位与**全部反哺标记**；
3. 解读不到、无法验证的内容写「待补充：<缺什么、去哪找>」，不编造、不推定；「禁止依赖方向」这类规则性结论尤其如此，无代码依据时一律待补充；
4. 某节确无内容可填时，按该节的生成提示处置：提示要求删除整节的，删除该节；否则删除该节内的示例、格式块与悬空结构（空表头等），只留一行「待补充：<缺什么、去哪找>」；
5. 生成提示与上述规则冲突时，以上述规则为准；生成提示本身也是挖空点，用完即删，不得反过来改变规则。

## 操作一：初始化

场景：仓库根目录缺少一份或多份模板同名文档。对每份待生成文档独立执行：

1. 按「读取优先级」取基准模板（**输入**：基准模板 + 项目现状）；
2. 按「文档定位」表的来源解读项目；全新项目信息不足时，以用户的需求描述为解读对象；
3. **🔴 CHECKPOINT · 🛑 STOP**：先把将创建的文件路径清单交用户确认，确认后再落盘；跳过条件见「免确认词表」；
4. 生成 `<仓库根>/<名>.md`（**输出**：新文档）；
5. 已存在的同名文档保持不动，在结果中提示可改走「更新」；
6. 按「执行纪律」的统一格式汇报。

**完成判据**：被处理的每份文档各有产出，其余每份（如有）各有一条跳过理由（「未点名」也算一条）；已存在的同名文档字节未变，并在汇报中给出核验输出。

> **免确认词表（三操作通用，唯一）**：用户本次请求的原话含**免确认词**（直接生成／直接写／直接落盘／直接更新／直接同步／直接改／不用问我／不用确认／无需确认）。**未命中枚举即视为不免确认**，不得自行外扩词表。跳过时须在回复首行引用该原话。本旁路同时覆盖「异常与兜底」表中一切需要用户交互的修复项：命中时**跳过该行的交互动作，但仍先执行该行的一线修复**；一线修复属**终态性放弃**（如「不写入并说明理由」）时直接取该行「仍失败兜底」；一线修复**可失败**（如复制模板、重试入口）时，失败后再取兜底；若该兜底本身仍是「问用户」，则取**保守终态**——不落笔、记为「待用户确认」并在汇报中列出。

## 操作二：更新

场景：仓库根目录已存在模板同名文档，需跟上项目现状。

1. 逐份重新读取文档现状与基准模板（**输入**：文档 + 基准模板）；
2. 逐章节对照，每个章节给出处置（**输出**：处置清单）；
3. **🔴 CHECKPOINT · 🛑 STOP**：先把「将改动的章节清单 + 处置」交用户确认，确认后再落盘；跳过条件见「免确认词表」；
4. 以最小变更落笔（**输出**：更新后的文档）。

更新规则：

- 每个章节的五选一处置：**补齐**（模板有而文档缺，按生成提示填空）／**修正**（与项目现状冲突的事实：命令、目录、依赖、令牌值，核实后改）／**保留**（文档有而模板没有的章节，它是「同步」的输入）／**无变化**／**不适用**（模板有而文档缺，但该节的生成提示授权无内容时删除：不生成该节）；
- 对照口径：以**归一化后的标题文本**匹配。归一化＝把标题中的 `{{占位符}}` 换成**通配符**（匹配任意文本，含空），并删除 `<!-- 注释 -->`；两侧标题在通配语义下相同、且 **`#` 层级一致**（数量相同）即为匹配（模板 `# {{项目名}}` ↔ 文档 `# 蓝鲸网关`、模板 `# {{项目名}} 设计系统` ↔ 文档 `# 蓝鲸网关 设计系统` 均匹配）。**文档标题节（H1）一律视为已存在**，既不判「补齐」也不反哺。归一化后仍不匹配的才算「文档独有章节」。章节顺序以基准模板为准，文档独有章节按原位保留；删节导致的编号漂移**不重编号**；
- 保持既有章节顺序与行文风格；人工补充与项目特性内容一律保留；
- **完成判据**：本次点名的每份文档，其每个章节都有一条处置，并在汇报中按章节列出处置与依据（「不适用」条目的合并口径见「执行纪律」）；标「无变化」须写出与基准模板的逐条对照结果（如「DESIGN.md 19 个挖空点均已填」，数量按「模板机制」的四形态口径计），仅凭印象标注不算。漏一个章节即未完成。

## 操作三：同步（反哺模板）

场景：项目文档演化出了基准模板中不存在的标题或内容结构。

1. 逐文档对比 `<仓库根>/<名>.md` 与基准模板（**输入**：文档 + 基准模板）；
2. 提取基准模板缺少的标题与表头，逐条给出处置：反哺／问用户／不适用（**输出**：反哺候选清单）；
3. **🔴 CHECKPOINT · 🛑 STOP**：把候选清单交用户确认，确认后再写入 `<仓库根>/templates/<名>.md`；跳过条件见「免确认词表」；
4. 标题原样追加、具体内容改写为生成提示后追加进模板，并带 `<!-- 反哺：<日期> 来源 <文档> -->` 标记（**输出**：更新后的仓库根模板）。

同步规则：

- 反哺范围：只反哺「结构」（标题、表头、组织方式）与跨项目通用的规则；
- 结构与内容的判定：标题（`#`/`##`/`###` 行）与表头一律原样反哺，不得自行改名、概括或翻译；段落正文、命令、路径、令牌、数值、日期一律视为项目值，还原成挖空点（改写为 `<!-- 生成提示：... -->`）；
- **对冲措辞不反哺**：由**填空过程**产生的括注与限定语（「建议」「依据…推断」「待核实」等）属项目值，反哺时剔除；项目文档中本就存在的合法括注标题不在剔除之列，按「拿不准」处置；
- 「拿不准」的判据与处置：标题或表头含项目专名（产品名、内部系统名、团队名、模块名、业务域）时即为拿不准。**🔴 CHECKPOINT**：列出候选问用户，不默默写入；命中「免确认词表」时一律记为「不适用，不反哺」并在汇报中列出；
- 方向单一：项目文档 → 模板；同步过程永不反向删改项目文档。

**完成判据**：项目文档中每个基准模板没有的标题与表头（**文档标题节 H1 除外**，它按对照口径一律视为已存在），都有一条处置（反哺 / 问用户 / 不适用），漏一个即未完成；**该份模板被判为项目自有、或复制失败而跳过时**，该份在项目文档侧的独有标题合并记为一条「不适用，理由：<模板非本技能产物／复制失败>，反哺无处落笔」，不再逐条展开；项目文档本身零改动，并在汇报中给出核验输出。

## 异常与兜底

流程假设环境理想，实操常遇下列异常。命中即按表执行，绝不静默跳过。

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| 技能自带模板文件缺失 | 跳过该份文档的处理，在汇报中说明缺失文件名 | 停止全部操作，请用户确认模板来源后重试 |
| 仓库根目录不可写 | 报告权限问题并列出待写入的完整路径 | 将待写入内容原样输出到对话，由用户自行落盘 |
| **目录层通过后**，`templates/` 内无同名文件 | 先从技能自带模板复制出同名文件，再写回 | 复制或写回失败则跳过该份并汇报，不改项目文档 |
| `templates/` 内已有同名文件但不是本技能模板（与技能自带模板无公共章节重合） | 跳过该份、其余照常处理，并在汇报中说明跳过的文件名 | 记为「非本技能产物，不落笔」并在汇报中列出该份未处理 |
| `templates/` 内已有其它文件、且不含任何本技能同名模板或反哺标记（判为项目自有目录） | 整目录不写入并说明理由 | 用户确认后照常逐份写入；用户未确认则记为「非本技能目录，不落笔」 |
| 用户点名管辖范围外的文档（README.md、CLAUDE.md、docs/ 等） | 说明本技能只管辖四份文档，拒绝处理并说明理由 | 用户坚持时，记为「超出管辖范围」，不落笔、不汇报为待办 |
| 用户拒绝候选标题的反哺 | 该标题记为「不适用」，不写入模板 | 请用户给出归类后再决定是否反哺 |
| **更新时**项目文档与模板同一章节冲突 | 以项目现状为准修正项目文档，不反向改模板 | 无法判断孰是时，列候选问用户 |
| 模板存在但格式损坏或挖空点被误删 | 以技能自带模板补齐缺失的挖空点（**挖空点缺失不属「公共章节完全缺失」**，按本条补齐，不跳过该份），项目值留在原处不动 | 无法判断以哪份为准时，列出差异问用户 |
| 四份文档已齐全时用户仍要求初始化 | 说明已齐全，改走「更新」并说明所选操作 | 用户坚持初始化时，按「更新」执行并在汇报中记录该分歧 |

## 执行纪律

- 动手前逐文档重新读取当前内容。项目文档可能已被并行会话或人工修改，会话早期读取的副本一律作废，凭旧副本断言「无变化」即错误；
- 一次调用只做一种操作；用户未点名操作时，按「有缺失文档 → 初始化缺失的，四份齐全 → 更新」判断，并说明所选操作；
- 用户只点名**管辖范围内**的部分文档时，只处理点名的那几份；点名范围外的文档按「异常与兜底」表拒绝并说明；
- 文档语言跟随项目主语言（默认中文）；
- 收尾汇报统一格式，逐文档列出：做了什么操作、动了哪些章节、遗留哪些待补充项、**本次新增/写入的文件清单**、**未改动文件的核验输出**。同一操作内反复出现的「不适用／不反哺」条目可**合并为一行汇总**（逐节列出节名）——仍满足「每章节都有一条处置」，不必逐条展开依据。这类条目跨轮必然重现（该章节在项目文档中确实不存在，是稳定事实），属正常，技能不为其设持久化标记。
- **核验方式（唯一）**：动手前逐路径记录「存在性 + sha256」作为基线，收尾时重算比对，输出逐路径「一致／不一致／缺失」。**不用 `git status --porcelain`**——它对被忽略路径即使改动也输出空，且存在未跟踪文件时输出必然非空，会给出错误结论；非 git 仓库同样用哈希。
- **基线范围（唯一，不随操作变化）**：**仓库根顶层与 `templates/` 内的全部文件**（逐路径记录存在性 + sha256），加这两处的**文件名清单**。二者文件数有限，成本可控。
- **范围边界（显式声明）**：本技能的**写入面只有仓库根顶层与 `templates/` 两处**。对**其它子目录**（`docs/`、`src/`、`node_modules/` 等）内的文件，在任何情况下不写入、不修改、不删除，也**不纳入核验**（递归代价不可控）。收尾汇报须写明「仓库根顶层与 `templates/` 以外的路径未核验」这一残留。
- **零改动判据**：基线范围内「本次操作不该动的路径」哈希一致，且文件名清单的新增条目**全部出现在「本次新增/写入清单」中**（初始化创建文档、同步首轮复制模板都属合法新增，不判越界）。**不该动集合＝仓库根顶层与 `templates/` 内的全部文件，减去本次允许改动的路径**：初始化允许新增本次点名的文档；更新允许改动本次点名的文档；同步允许改动本次目标的模板。其余路径（README.md、CLAUDE.md、未点名的文档与模板）一律不该动，改动或删除都算越界。
- **新增/越界核验**：收尾列出**仓库根顶层与 `templates/` 的实际文件名清单**，与「本次新增/写入清单」逐项比对——**越界的定义是「出现了不在本次清单中的新条目」，与是否上报无关**（如实上报不构成豁免）；清单有而实际无者即虚报。基线有而实际无者即**删除**，同样算越界。两处不符都算未完成，`:13` 的硬约束由此可核验（**限于仓库根顶层与 `templates/` 两处**）。
