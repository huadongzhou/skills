六项 P0
foundation文件层判据缺阈值 → 会覆盖用户自有文档

事实：「公共章节＝除 H1 外的标题与表头」，而 templates/AGENTS.md 的标题全是通用名（项目介绍 / 技术架构 / 项目目录 / 开发命令 / 编码开发…）。

后果：项目自带的 AGENTS.md 只要用到一两个通用标题，就判为「部分重合 → 模板损坏」，走补齐路径覆盖用户文件，直接违反 L13「其余文档不创建、不修改」。

处置：加最小重合阈值——公共章节重合 ≥2 个特征标题（如 ## 场景上下文、### 约束），否则判为非本技能产物、跳过。

跨技能免确认旁路两份实现，语义已漂移

事实：cognition L63–68 带否决条件（否定 / 延后 / 语气），foundation L75 只有正向枚举、无否决条件。

后果（真 bug）：「不要直接生成 AGENTS.md」——foundation 命中枚举判为免确认直接落盘，cognition 对同一句话正确判为不免确认。同仓库两技能处置相反。

处置：统一判定文本；不要用跨目录 shared/（skills.sh 按技能目录安装，会静默断链）——各放一份到自身 references/，正文只留指针。

cognition跳过条件是一台字符偏移伪解析器

事实：L63–68 用「其后 6 字内」「前 4 字内」「后 8 字内」「后 2 字内」逐一枚举否定词、延后词、语气词及其豁免，5 行约 400 字。

判据：negation 驱动（满篇被禁词）+ no-op（判断用户是否授权是模型自带语用能力）+ sprawl（挤掉第一步判据的注意力）。

处置：塌缩为正向一句——「仅当用户原话显式授权免确认时才跳过；含任何保留、延后或疑问语气一律不跳过」。实测仍误判再叠最小护栏。

cognitiondescription 复述正文身份，同一 branch 写两遍

「九维 / 三件套 / 反转 / 留白不编造」全是 L8 / L12 / L30 / L126 已载身份；「深挖某个实体」与「构建/生成知识深度树文档」是同一 branch 的同义重写。

改写：知识深度树：给定任意实体产出九维深度文档，以「反转」把默认认知翻过来。当用户要求深挖某个实体、或要生成知识深度树文档时使用。

foundation归一化对照口径寄居「操作二」，却被公共节与「操作三」引用

定义写于 L89（操作二），引用方是 L28「污染防护」（公共节）与 L110（操作三判据）→ 各分支被迫跨读另一个分支，违反 branching 测试。

处置：上移为「模板机制」下独立 reference **对照口径**，三处改同义引用。

foundation免确认词表嵌在「操作一」，却自称三操作通用

L75 自称「（三操作通用，唯一）」，物理位置却在操作一第 3 步之下，被 L68 / L83 / L99 三处引用——全流程唯一旁路闸门放错分支。

处置：提为顶层公共节 ## 免确认旁路，三处 CHECKPOINT 只留引用，并按跨技能项补否决条件。
