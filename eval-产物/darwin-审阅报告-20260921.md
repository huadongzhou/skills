## 一、结论先行

两个技能**结构成熟、实测可用，但都不到 80 分线**，且短板结构不同：

1. **cognition 的最大缺口是 dim8 实测表现（加权缺口 6.25，全表最高）**。它在 happy path 上真能跑出高质量可追溯产物（9/9 维、9 条三件套、9 条反转全部带 ≥2 来源），但在「私有实体」场景下产出**不如不带技能的 baseline**——用户拿到的是九节全空的文档。
2. **foundation 的最大缺口是 dim2 工作流清晰度（4.88）与 dim7 整体架构（4.25）**。红队找到两处**高危架构裂缝**（硬边界自破、反哺闭环断裂），本轮首次暴露，上一轮未发现。
3. **共性是「宣称强度 > 可检查性」**：两个技能都把「字节未变 / 零改动 / 外行反应是『等等，真的？』/ ≥2 独立来源」写成硬判据，却都没给任何可执行的验证手段。
4. **上一轮的成果被本轮实测确认有效**：显性 `🔴 CHECKPOINT · 🛑 STOP` + 授权旁路确实既满足 dim4，又不破坏单轮可用性（实测 T3 确认可一轮落盘）。
5. **仍有残留的编造压力路径**：cognition 的异常表豁免了「来源」却没豁免「案例」与「来源不足」；这是本轮唯一被两名判官独立指认的高危缺口。

**结论**：两技能均可进入 Phase 2，但 **foundation 的优先修复项应重排**（先修架构裂缝，再修 dim2），cognition 则应优先处理「案例豁免缺失」而非继续堆结构分。

## 六、共性问题

### C1 · 判据可验证性缺口（两技能，最高频）

两个技能都把强断言写成完成判据，却都没给验证手段：

| 技能 | 位置 | 宣称 | 缺失 |
|---|---|---|---|
| cognition | `L26` | 「单独拿给一个外行看，他的反应是『等等，真的？』」 | 无操作定义、无受试者 |
| cognition | `L66` vs `L81` | 「≥2 独立来源」/「≥1 支撑来源」 | 两套口径，且无法核验条数 |
| foundation | `L67` | 「已存在的同名文档**字节未变**」 | 无 diff / 哈希步骤，`L126` 汇报格式无此栏位 |
| foundation | `L105` | 「项目文档本身**零改动**」 | 同上（本次实测靠判官自己算 md5 才验证成功） |

**改法**：把强断言从「结论」改为「结论 + 证据口径」。例如 foundation `L126` 汇报格式增两项——「本次写入的文件绝对路径清单」与「未写入文件的核验输出（`git status --porcelain` 为空）」。

### C2 · 口径不一致（两技能各 2-3 处）

- cognition：来源条数 `L66`(2) vs `L81`(1)；留白标记 `L67`/`L70`/`L100` 三套。
- foundation：初始化判据 `L67`(四份) vs 更新判据 `L83`(点名范围) vs 执行纪律 `L124`(点名范围)；反哺 `L101`(一律) vs `L102`(拿不准)。

**注意**：口径不一致比措辞不一致危险——它让**最宽松的那一处成为事实标准**（执行者会挑最省事的口径交差）。

### C3 · 豁免不完备导致残留编造压力（cognition 独有，本轮最高风险）

异常表为「来源」建了豁免（`L101`），却没为**案例**（`L18`/`L79` 要求有名有姓、可追溯）和**来源不足**（`L66` 要 2 条，异常表 `L98` 只处理「两条互相矛盾」）建豁免。`L81` 又把「三件套齐全」设为硬判据——面对无公开案例的实体，执行者的唯一「合格」出路是**造一个案例填进去**。

**实测反证**：cognition 在 T1 上确实两次主动弃用了单源断言（「1952 年通用电气首次制备固态电解质」仅百度文库单源、「硫化锂 650 万元/吨」摘要截断无法核），说明纪律在 happy path 有效；但 T2 的私有实体路径之所以没编造，靠的是 `L59` 检查点而非异常表设计——**护栏是偶然而非必然**。

### C4 · 检查点已达标，但覆盖不均

上一轮补的显性标记 + 授权旁路本轮**经实测确认有效**（`grep` 命中 cognition 2 处、foundation 3 处；T3 确认可一轮落盘）。剩余问题：

- cognition：`L59`/`L85` 旁路举证不全（只举「直接生成并保存」，未含「不用问我」等同义指令——实测靠语义推断命中）；第三步（落笔）无 gate，而它恰是编造发生地。
- foundation：**操作二（更新）零检查点**，而更新直接改写既有文档、触碰人工补充内容，风险高于初始化。

## 七、分技能发现

### 7.1 cognition — 知识深度树

**实测结论：happy path 上是真骨架，私有实体场景不如 baseline。**

| 用例 | 结果 | 关键数据 |
|---|---|---|
| T1 固态电池 | 成功（检查点拦一轮后经确认完成） | 9/9 维覆盖、9 条三件套、9 条反转、**9/9 反转带 ≥2 独立来源**、占位符残留 0、模板注释残留 0；产出 19KB vs baseline 3.9KB |
| T2 Bluefin | 部分成功 | 零无来源断言（纪律生效），但产出**九节全空文档**；baseline 反而给了「8 项待补信息 + 分析框架 + 敏感信息提醒」，可用性更高 |
| T3 Transformer | 判定正确 | `L59`/`L85` 旁路命中，可一轮落盘，但须保留「树序大纲 + 检索无果项」汇报 |

**实测新增风险（判官未预见）**：T2 检索并非「无返回」，而是返回了 **4 个同名无关实体**（bluefin.io 去中心化金融 / projectbluefin Linux 发行版 / bluefin.com 支付安全 / Bluefin Robotics 水下机器人）。这比「无返回」更危险——它给了模型可抓取的文本。`SKILL.md` 对此只有 `L101` 一句泛化留白，**没有「同名实体污染」的显式警告**。

**结构性缺陷（按优先级）**：

1. `L18`/`L79` 案例判据无豁免行（见 C3，最高风险）。
2. `domains.md:L25` ○「次（简述）」与 `SKILL.md:L81`「每个保留维度三件套齐全」定义冲突——○ 属保留而非并入，字面执行被迫展开，与 `L8`「共识压缩到一句话」相悖。实测 T1 的「谱系」「争议」两节因此超展开。
3. `L101` 私有实体路径**只有留白、无索取动作**——异常表未要求「主动向用户索取一手信息」。
4. `domains.md:L62` P1 人物反转主色调为「公众形象 ≠ 真实动机」，对**在世个人**几乎只能靠二手推测，而全文无针对在世个人的加固规则（中高危）。
5. `templates/knowledge-doc.md:L34` 相对路径不可达（轻）。

**两处高危架构裂缝（本轮首次发现）**：

**F1 · 硬边界自破** — `L13`「其余任何文档…不创建、不修改、不迁移」，但 `L20`/`L115` 要求在 `<仓库根>/templates/` 下**复制出同名文件**。该文件不属 `L12` 的四份、正落在 `L13` 的「等」字覆盖内，全文无豁免句。
→ 改法：在 `L12-13` 间加一句「仓库内 `templates/` 下的四份同名模板副本视为本技能的工作产物，不受本节『不创建』约束」，并在 `L116` 拒绝清单中显式排除。

**F2 · 反哺闭环断裂** — `L19` 规定初始化/更新**只读技能自带模板**，全文无任何规则让它们回读仓库模板。于是操作三花整节建立的「项目结构反哺回模板」通道，其产出**永远不会被后续初始化/更新消费**——同一项目第二次初始化仍从原版模板起算，反哺内容等于写进了死文件。
→ 改法：`L19` 改为「初始化/更新读技能自带模板；**仓库内存在 `templates/<名>.md` 时以它为基准**（同步产物优先）」；或明确写出操作三产物的消费者是谁。

**F3 · `L101` 与 `L102` 判据冲突** — `L101` 说标题「一律原样反哺」，`L102` 说「找不到同类兄弟节点即拿不准 → 问用户」。按 `L102` 字面读，**任何新结构天然找不到同类兄弟节点 → 一律拿不准 → `L101` 的自动反哺永不触发**。实测 T3 被迫对「同类兄弟节点」取宽松解释（同层级、同角色）才使流程可跑。
→ 改法：`L102` 的判据收窄为「标题含项目专名」单一条件，删去「找不到同类兄弟节点」这一自我否证的条款。

**实测附带发现**：`L101` 的「原样反哺」会把**初始化时的对冲措辞**污染进模板——T3 反哺的表头 `| Token | 值 | 语义用法（建议，依据值级推断） |` 中的括注本属填空时的限定语，按「不得自行改名、概括或翻译」只能原样带入。

**次要缺陷**：`L33` 悬空指针、`L37` 挖空点定义不完整（42 处生成提示 + 2 处占位符 + `TODO.md:L11` 一处无标记的正文型挖空点）、`L83` 示例「3 个挖空点」与实际数量不符、`TODO.md` 两个同类示范块删除规则相反、操作二/三缺编号步骤。

## 十、方法与局限

**已做**：6 名独立子代理盲评（judge 与主代理分离）；主代理对 17 条高严重度断言逐条回源核验（行号已复核）；两技能端到端真跑（非 dry_run）；baseline 对照实跑；判官分歧逐条裁决。

**未做 / 局限**：

3. **端到端仅覆盖 3+3 用例**：cognition 的 T3 与 foundation 的 T2 为判定而非完整执行；未覆盖跨会话、多轮确认、并发修改等场景。
4. **测试 prompt 未经用户确认**：darwin Phase 0.5 要求先展示确认。因本次为「完成审阅」指令，主代理自行设计并直接执行，prompt 全文已记录于 `test-prompts.json`，如需调整可重跑。
