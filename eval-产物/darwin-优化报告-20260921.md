## 四、核心改进：三类最高价值修复

### 4.1 「宣称强度 > 可检查性」→ 每条硬判据配核验手段（两技能共性）

审阅发现两技能都把「字节未变 / 零改动 / ≥2 独立来源」写成硬判据，却都没给验证手段。修复分三步：

1. **定义范围**：`不该动集合 = 仓库根顶层与 templates/ 内全部文件，减去本次允许改动的路径`（此前「不应改动文件」全文无定义）。
2. **选对工具**：弃用 `git status --porcelain`（实测：对被忽略路径即使改动也输出空；存在未跟踪文件时输出必然非空），改用「存在性 + sha256」。
3. **补上新增与删除**：哈希只能发现「清单内文件被改」，结构上看不到新增。补「文件名清单逐项比对」——`实际有而清单无 = 越界创建`、`清单有而实际无 = 虚报`、`基线有而实际无 = 删除`。

**实测验证**：注入 5 类副作用（误改模板 / 仓库根新建 `CLAUDE.md` / 误改 `README.md` / 删除 `README.md` / 合法写入），新体系 5/5 全部检出；旧体系漏检 2 类。

### 4.2 foundation：`templates/` 归属门禁自锁（最严重的一条）

原判据「该目录为空或已含本技能的四份模板文件」是**全有或全无**。而技能自己的一线修复是「逐份复制同名文件」，必然产出「只有 1～3 份」的中间态 → 第 2 轮起被自己的规则拒绝，**永久自锁**。

实测复现：`轮1 复制 TODO.md ✅ → 轮2 同步 AGENTS.md ⛔ 被拒 → 轮3 再同步 TODO.md ⛔ 连原本合法的目标也被拒`。

修复：改为**目录层 + 文件层两层判据**。
- 目录层：目录不存在 / 为空 / 含任一「本技能痕迹」（按文件名判定）→ 可写；已存在且内有其它文件、又不含任何痕迹 → 判项目自有目录，整目录不写入（可用户确认解锁）。
- 文件层：逐份判「同名文件不存在 / 与本技能自带模板有公共章节重合」→ 可写；**完全无重合** → 跳过该份。

实测：10 种目录状态**每种都有唯一、无歧义的出路**；多轮逐份同步不再自锁。

### 4.3 cognition：留白三分类与两条豁免态

原技能只有「留白」一个概念，导致：私有实体（无检索对象）被强制要求附 ≥2 条检索式 → **只能编造或判未完成**；工具不可用既非「查了没查到」也非「该问用户」→ 无类别可归。

修复：
- **留白分三类**：检索型（附检索式 ≥2 + 日期 + 返回条数）／索取型（问用户，不要求检索式）／工具不可用（未执行检索，不要求检索式）。四处判据（第二步完成判据、留白标记格式、收尾汇报口径、模板附录）全部回填。
- **两条豁免态**：①整节点留白的节点；②已写明「本维无反直觉结论」并附凭据的节点。二者均不受「三件套齐全」与「至少一条反转」约束——把执行者从「编造反转 vs 判未完成」的二选一中解放出来。
- **私有实体来源口径**：来源为「用户提供的一手信息」且该实体无公开来源时，反转不适用「≥2 独立来源」，改标「来源：用户提供，未经外部核验」，不计入单源存疑；公开实体的孤证反转不得借此豁免（闸门）。

实测（R5）：豁免态②被正确接纳，**零编造、零判死**。

## 六、遗留项与取舍（诚实披露）

### 6.1 已知取舍（设计决定，非缺陷）

1. **cognition 退化场景产出价值低**。私有实体或工具不可用时，文档退化为留白标记堆。这是「宁可留白不可编造」的必然结果，**不予修复**；但终版补了「若换入口后仍无返回，走工具不可用留白」与「实测为准」两条，避免无谓退化。
2. **foundation 子目录不可核验**。核验范围显式限定为「仓库根顶层 + `templates/`」，`docs/`、`src/` 内的越界写入**不可发现**（递归代价不可控，已实测 200 个 `node_modules` 文件会把核验对象从 12 个推到 215 个）。终版把这一盲区**显式写入条款并要求在汇报中声明残留**——把「未定义的漏洞」变成「已声明的边界」。
3. **foundation 反哺撤销不具持久性**。撤销只作用于模板，下一轮同步会把它重新反哺。终版明确声明「技能不自动回滚」，把选择权交还用户。
4. **foundation「不适用」条目跨轮重复**。该章节在项目文档中确实不存在，是稳定事实，必然每轮重现。终版允许合并为一行汇总，但不设持久化标记（避免向项目文档写入技能内部状态）。

### 6.2 体量警示（唯一需要后续关注的问题）

| 文件 | 基线 | 终版 | 增幅 |
|---|---|---|---|
| `cognition/SKILL.md` | 8,628 B | 15,578 B | +81% |
| `foundation/SKILL.md` | 10,272 B | 18,108 B | +76% |

两名终局评分官均独立指出体量问题：cognition「旁路段偏臃肿，约 1.5KB 属过度工程」；foundation「**略偏臃肿**，18.1KB 服务 4 份共 14.2KB 的模板，膨胀主要来自长复合句而非新增判据，解析成本已被推到读者侧」。

**根因**：每一轮修复都在 SKILL.md 内追加「判据 + 例外 + 豁免 + 声明」，从未做过外迁。这是 darwin 棘轮机制的副作用——**只保留改进，不主动重构**。

**建议（需独立验证，本轮未做）**：把「异常与兜底」表（cognition 9 行 / foundation 10 行）迁至 `references/edge-cases.md`，SKILL.md 保留 3 行强制读取指引。预计各减 1.5–2KB。**风险**：references/ 是按需读取，若执行者不读，异常处置能力会丢失——迁移后必须重跑实测验证，不能仅靠文本推演。

### 6.3 终局残留（P2/P3，已记录未修）

| 技能 | 项 | 严重度 |
|---|---|---|
| cognition | 旁路窗口以「6 字内 / 前 4 字 / 后 8 字」写成散文规则，实操仍有歧义（评分官建议「本可用一句话 + 判断力表达」） | P2 |
| cognition | 反转判据「单独拿给一个外行看，他的反应是『等等，真的？』」依赖主观判断，非机械可判 | P2 |

## 八、方法与局限

- **rubric 口径**：8 维（结构 60 + 效果 40）。分数由单名评分官给出，**未做多判官 triage 平均**，因此 ±3 分的绝对精度不可依赖；可信的是**相对变化**（配对盲评 55:43 / 56:35）。
- **实测环境**：Windows + Git Bash；`agent-browser` 不支持 Windows，截图改用 `playwright-core` + `chrome-headless-shell`。检索类用例使用真实 WebSearch，全程可联网。
- **未做的事**：未做跨模型实测（单一模型环境）；未做长期稳定性观察（仅单日 12 轮）；未做体量重构（见 6.2）。
- **诚实边界**：本轮红队终审给出「无 P0、无 P1、可交付」，但**红队每轮都能找到新问题**（第 4–10 轮各 1–3 个 P1）。「可交付」的含义是「剩余问题不阻塞执行、不产生错误产出」，不是「无缺陷」。
