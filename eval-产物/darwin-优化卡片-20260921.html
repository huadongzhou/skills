三、三类最高价值修复

P0 · foundation

templates/ 归属门禁自锁

原判据「目录为空或已含四份模板」是全有或全无，而技能自己的一线修复（逐份复制）必然产出「只有 1～3 份」的中间态 → 第 2 轮起被自己的规则拒绝，永久自锁。

改为目录层 + 文件层两层判据：目录层看「是否存在本技能痕迹」，文件层逐份看「同名文件是否存在 / 有无公共章节重合」。

实测：旧版 轮1 复制✅ → 轮2 ⛔被拒 → 轮3 连合法目标也被拒；新版 10 种目录状态各有唯一出路，多轮同步不再自锁。
P0 · 两技能共性

宣称强度 > 可检查性

两技能都把「零改动 / 字节未变 / ≥2 独立来源」写成硬判据，却没给任何验证手段。三步修复：定义范围（不该动集合）→ 选对工具（弃 git status，改 sha256 + 存在性）→ 补新增与删除（文件名清单比对）。

实测：注入 5 类副作用，新体系 5/5 检出；旧体系漏检「仓库根新建 CLAUDE.md」与「删除 README.md」。
P0 · cognition

留白三分类 + 两条豁免态

原技能只有一个「留白」概念：私有实体（无检索对象）被强制要求附 ≥2 条检索式 → 只能编造或判未完成。改为检索型／索取型／工具不可用三类，并把四处判据全部回填。

另设两条豁免态（整节点留白 / 已写明「本维无反直觉结论」），把执行者从「编造反转 vs 判死流程」的二选一中解放。

实测 R5：豁免态②被正确接纳，零编造、零判死。

五、遗留项与取舍（诚实披露）

唯一需要后续关注的问题：体量膨胀。 cognition +81%、foundation +76%。两名终局评分官独立指出体量问题（cognition「旁路段约 1.5KB 属过度工程」；foundation「略偏臃肿，膨胀主要来自长复合句而非新增判据」）。 根因是 darwin 棘轮机制的副作用——只保留改进，不主动重构。 建议（需独立验证，本轮未做）：把「异常与兜底」表迁至 references/edge-cases.md，各减 1.5–2KB；风险是 references 按需读取，迁移后必须重跑实测，不能仅靠文本推演。
  • cognition 退化场景产出价值低（私有实体 / 工具不可用时退化为留白标记堆）——「宁可留白不可编造」的必然结果，不予修复。
  • foundation 子目录不可核验——核验范围显式限定为「仓库根顶层 + templates/」，docs/、src/ 内越界不可发现（递归代价不可控）。已把盲区写入条款并要求汇报声明残留，把「未定义的漏洞」变成「已声明的边界」。
  • foundation 撤销不具持久性——撤销只作用于模板，下轮同步会重新反哺。已明确声明「技能不自动回滚」，选择权交还用户。
  • 终局残留 P2/P3：旁路窗口以字数写成散文规则仍有歧义；反转判据「外行反应是『等等，真的？』」依赖主观；foundation「一律原样反哺」与「专名例外」存在措辞张力。
诚实边界：本轮红队终审给出「无 P0、无 P1、可交付」，但红队每轮都能找到新问题（第 4–10 轮各 1–3 个 P1）。「可交付」的含义是「剩余问题不阻塞执行、不产生错误产出」，不是「无缺陷」。
分数由单名评分官给出，未做多判官 triage 平均，因此 ±3 分的绝对精度不可依赖；可信的是相对变化（配对盲评 55:43 / 56:35）。
